WHAT CHANGED 47: LATE OFFLOAD COMPLETIONS IN THE DST, SHARED SPLITMIX64, TRACING TEST GAPS

Summary
The simulator can now hand an offload job's completion over one hand-over late, but only for a job whose work sent through the transport. This models a stream-mode worker that sends a request and queues its completion after a hand-over has already taken the answer. Before, the DST could not produce that race, so the trace logic that holds such an answer back one flush was covered only by unit tests. Scripted runs keep exact timing; half the other runs draw a chance of it. The SplitMix64 finalizer, which was copied in `RequestTraces` and `RequestTraceIds`, now lives once in `controller.env.SplitMix64`; sampling and trace ids are unchanged, and tests pin both. The node's `Outcome::Searched` is now `Outcome::Expired`, true only for a job dropped for waiting past `MaxWait`. The old name was true for probes and wrong-region jobs too, and production never read it. New tests cover the `SimTracing` checker itself, node timing histograms (a later copy is not counted, an abandoned request's answer is, a probe's never), a dead holder's `world.lag`, `Controller.Settings` validation, the production tracer provider's id generator, a trace with an answer but no send, and the default sample rate. The fuzz coverage tier now also claims late streamed sends, runs traced at a share below 1, traced resends, and traced answers turned down for their world sequence. The trace check now allows for answered traces that a controller still held when it restarted.

Decisions made without explicit instruction
- Only work that sent is made late. Work that sends nothing gives the same outcome as a slower encode, which the sim already models with its random work time, and making it late would also delay batch sends and world frames, which could push runs over the SLO for a reason production does not have. The alternative was to make any completion late.
- A late completion is exactly one hand-over late, not a random delay. The controller holds an answered trace back one flush only, so a longer delay would report a trace with no send, which `SimTracing` flags. In production the worker queues its completion microseconds after it sends.
- The chance is drawn in `SimRun` from its own derived stream (`late-completion-chance`), and each per-job draw from another (`late-completions`), made only when the chance is above 0. A new `Scenario.Chance` would have shifted every existing seed's scenario draws. Runs with chance 0 replay exactly as before. Runs with a chance above 0 replay deterministically, but differently from before.
- `SimRun.lateCompletions(chance)` sets it before `go()`, so `describe()` reports what the run used. Scripted runs default to 0 because their tests assert exact timing.
- `Expired` is the inverse of the old field, not a rename, so that a default `Outcome{}` means a job that was run.
- `SplitMix64` sits in `controller.env`, next to `SeededRng`, because the mod already depends on the controller module and both callers hash ids rather than draw from an `Rng`. `nth(seed, n)` names the formula `RequestTraceIds` already used, so trace ids do not change.
- The first sweep with late completions found that a trace held back for its send is lost when the controller restarts before the next flush. The DST's check that "every answer has a trace" did not allow for that. This is a gap in the harness, not a controller bug: a stopped controller loses its unreported traces just as it loses its open requests. `Controller.tracesUnreported()` now counts the answered traces a controller still holds, `SimRun` sums that count at each restart, and `SimTracing.check` allows exactly that many. The alternative was to flush pending traces on restart. A real crash cannot do that, so the DST would then claim more than production delivers.
- `Telemetry` exposes a package-private `tracerProvider(...)` so a test can check that request traces take their ids from `RequestTraceIds`. Testing the full SDK took 3 s, because the meter provider's last export retries against a closed port. The tracer provider alone exports nothing when no span ends.
