WHAT CHANGED 49: WORLD LAG FROM THE ASSIGNMENT, BLOCKS RUN CLEANUP, NO TRACING ON THE NODE

Summary
`world.lag` is now set for every node on every tick. Before, a node whose last heartbeat named none of its region (one that lost its area, or had not yet applied a new assignment) was skipped, so its gauge kept its last value. Now such a node counts from the sequence named by the last assignment it was sent, or from where the log stood when it became a holder if it was sent none. `WorldStreams` records that sequence per holder and exposes it as `assignedSequence`. This supersedes the "nothing for a node that has reported no area of its region yet" rule from entry 46. The e2e `blocks` run now removes what it built at the end: the door, the redstone blocks, the sticky piston with its block, and the sand. The dev world persists, so later local runs no longer start with these blocks in place. The node no longer links the OpenTelemetry C++ SDK. `obs.hpp`, `obs.cpp`, their test, the `MAESTRO_WITH_OTEL` CMake option and Makefile variable, the opentelemetry-cpp fetch, and the `--otlp` flag are gone. The node created no spans, and the spec says nodes export nothing.

Decisions made without explicit instruction
- The fallback lag counts from the last assignment's sequence rather than reporting a separate "holds its area" gauge. It keeps one gauge, and the value is a real count: the node has confirmed none of those frames. The cost is a short rise after each fresh assignment, until the node's next heartbeat (at most about a second). That rise is the snapshot the node still has to apply. Entry 46 avoided this to prevent a spike on every new link. A resumed link names its region in its first heartbeat, so it shows no rise.
- A holder that has never been sent an assignment (one that has not linked yet) now shows every frame produced for its region since it became a holder. Before, it showed nothing.
- `--otlp` is now an unknown flag, so a command line that still passes it fails with the usage text. Accepting and ignoring it was the alternative; nothing in the repository passes it.
- `clear_blocks` runs only at the end of a `blocks` run that got that far. A run that fails partway can still leave blocks behind. Clearing at the start of every run was the alternative, but it would also overwrite whatever the world held at those positions in a world that never had a `blocks` run.
- Build directories configured before this change keep a `MAESTRO_WITH_OTEL` entry in `CMakeCache.txt`. It is unused and harmless.
