MAESTRO

PROJECT OVERVIEW

Server-side Minecraft 26.1 mod, pinned permanently (no version updates). Offloads in-game A* pathfinding computation from the Java server to horizontally scalable C++20 compute nodes, allowing mob counts beyond vanilla limits. Purpose is educational: an experiment in latency-sensitive, high-availability distributed systems, not a polished gameplay mod.

COMPONENTS
Java server mod: authoritative world state, mob/tick logic, node orchestration, failover. Pathfinding is intercepted at `PathFinder.findPath` for single-target searches whose path finder and evaluator are exactly `PathFinder` and `WalkNodeEvaluator`; subclasses (the Warden's path finder, the Creaking's evaluator) and everything else stay vanilla. Only calls made inside the navigation's `moveTo` methods or `MeleeAttackGoal.canUse` are offloaded, since those follow the path they get; a caller that only reads a path, as to judge whether a target can be reached, would take a placeholder for the answer, so it stays vanilla. So does a search in which two nodes could share vanilla's lossy node hash (`Node.createHash`), which the node's exact node table cannot reproduce, and one whose evaluator footprint (width x height x depth cells, as `NodeEvaluator.prepare` sizes it) is over 512 cells, since a search's cost grows with it and admission assumes requests cost about the same; the node refuses such a profile too. The start node and the profile are resolved on the server between the evaluator's `prepare` and `done`, since `onPathfindingStart` may change malus (the Sniffer's). A call issues a request. While it waits, the call returns the mob's live path if it follows one, so a mob chasing a moving target keeps moving, or else a hold-in-place path (one node at the mob's own block, kept from finishing and from stuck detection); the real path replaces either when it arrives, from the node nearest the mob among its first few. A null would end goals such as `RandomStrollGoal` at once. A request the controller refuses at admission is searched on the server in the same call, through the failover below if its region's nodes cannot take it now; one dropped later ends a hold, and the goal asks again. A mob waits only while it follows its placeholder and its navigation was handed it after the call, so a caller that searches and then declines, as the Drowned's attack goal may, does not have the answer applied. A mob that no longer waits when the tick's work ends cancels the request; judging it then, not when the navigation drops the placeholder, lets a goal that replaces another hand the navigation the same path back. An answer that arrives after its mob moved on serves one later call for the same start and target within 10 ticks. In `offload: shadow` mode vanilla answers every call and the node's answers are only compared with it.
C++20 compute nodes: run A* pathfinding on world data sent by the server. The search sits behind one interface, chosen once at startup and reported on connect.
Wire protocol: Flatbuffers. Blocks sent as Minecraft PathType enum ordinals, not raw block types (the PathType enum is mirrored in the schema so the ordinal contract is explicit). Cells carry the per-block PathType (getPathTypeFromState, a pure function of one block state) and the block's collision height in sixteenths; neighbor-dependent and mob-dependent types are resolved on the node at query time, which keeps the delta contract at exactly one cell per block change. Chunk state is column run-length encoded, so its size tracks terrain complexity rather than world height. Mob metadata sent as low-cardinality IDs plus relative start/target positions and the per-call search inputs: reach range, the path length and visit bounds, and the mob's max fall distance (getMaxFallDistance reads its target and health, so it varies per call). The WalkNodeEvaluator inputs (footprint, per-PathType malus, and door/step/float/fence capabilities) are live per-instance state, not per-type: goals and mob code change malus and door abilities at runtime, and footprint varies with age, so a profile is interned by content and named per request. The first request naming a profile a node does not hold registers it and is given up, which normally keeps the profile a tick ahead of any request that needs it; a request that still overtakes it (a TCP retransmit can hold the control channel back) is answered `UnknownProfile` and dropped. Buffers reused, serialization done off main thread to avoid GC/lag.

COMPUTATION SEMANTICS
Best effort and eventually consistent. The node rebuilds getPathTypeStatic from the per-block types it holds: the OPEN-over-solid promotion that reads the cell below, then checkNeighbourBlocks. That scan must match vanilla exactly, including its dx/dy/dz iteration order over -1..1 skipping the center column, and its return on first hazard found, which is what decides cells bordering more than one hazard. Only A* is offloaded; other mob movement types (e.g. random walk) stay local. Scoped to land mobs only: the offload reproduces Minecraft's ground pathfinding (WalkNodeEvaluator); swimming, flying and amphibious evaluators stay local. Wall climbing is navigation behaviour rather than an evaluator, so a climbing mob's search is offloaded and its climbing stays on the server. Overworld only, no other dimensions (disabled by the mod). The wire carries each block's collision height, rounded up to a sixteenth, but not its shape, so `getFloorLevel` is exact to that sixteenth (only rare shapes such as the lily pad at 1.5/16 move) and `hasCollisions` treats every cell as a full-width box of that height, read without the mob, so blocks whose collision depends on the entity (powder snow, scaffolding) can differ. These approximations are intentional, as is ignoring the world border, which vanilla's collision checks include. A collision height that changes with no block change (a shulker box lid, a block a piston is moving) stays as last sent, and a moving block's height is clamped to its cell. Vanilla's search sees no entity collisions (its `PathNavigationRegion` holds none), so the node matches it there. Vanilla's region holds only the chunks within `maxPathLength + 8` of the mob and reads air past them, while the node reads its whole area, which differs only for mobs about 4.5 blocks wide or more. Vanilla may read per-block types through `ServerLevel`'s `PathTypeCache`, which can hold stale values; the node always reads its current cells. Cells carry no fluid, so "in water" means a cell typed WATER. The node never receives the mob's position: the two evaluator branches that read it (the collision sweep off a fence or closed door, and the rail check) use the start node instead. Otherwise the search is a decision-for-decision port of PathFinder and WalkNodeEvaluator, float rounding and tie-breaking included.

NODE MODES
Stateful (default): nodes hold delta-synced world shards, sent a chunk at a time. A node holds its whole area as air until a chunk arrives, which is what vanilla reads for a chunk the server is not holding, so a region serves requests without waiting to be complete and a chunk leaving costs one frame rather than a resend of the region. World divided into square, full-height regions with a halo buffer around each, so mobs near a boundary are shared with neighboring nodes. Region ids come from a per-run counter starting at 1, and regions never overlap. A node holds one region's area at most, so a dead node's region goes to a node holding none. A region may have several holders, which are sent its one world stream and split its mobs by id. Columns are carried at full height with no vertical trimming: run-length encoding already makes height nearly free. The halo is one pathfinding horizon wide (~64 blocks) and its cost grows as ((R + 2H) / R)^2, so region size is at least 4x the horizon (~256 blocks). A node reads past its area as air, so a request is sent only if every block its search reads lies in the area: `ceil(maxPathLength) + floor(width + 1) + 1` blocks around its start horizontally; otherwise it stays on the server. A node holds its area as immutable versions: a delta publishes a new version sharing untouched columns, and a search pins one version throughout. Chunks are read on the main thread under a per-tick budget, so a region sent again in full arrives over several ticks. Two sub-modes, both to be benchmarked: batch (all mob requests within a tick sent together, +/- jitter) and stream (requests sent immediately).
Stateless: nodes receive a full snapshot per request, trimmed to pathfinding-relevant surface blocks only (not the entire world). Distributed across nodes via power-of-2-choices. Sharding/halo concepts don't apply in this mode. Bandwidth inefficiency is intentional, for comparison purposes; no RLE or similar compression, to keep complexity down.

DATA STREAMS
Two separate streams: world changes and mob pathfinding requests. World and control streams are TCP, each on its own node port; the request stream is UDP, one frame per datagram, answered to the address it came from. The two TCP connections form one link: the controller opens each with a `Join` naming its run and connect attempt, a node serves one link at a time, a `Join` of another run or a later attempt replaces the link, and losing either connection loses it. A connection that opens with anything else, or names an earlier or lost attempt, is closed and leaves the link alone. Profiles and request ids belong to the link, so a node forgets them with it and keeps its world state. A node refuses an assignment of another run than the link's, of run 0, or a fresh one behind the stream it holds, as a frame it cannot apply. Every request frame names its run and region and every answer its run, since datagrams outlive links: a node drops a frame of another run and answers a request for another region as if it held no area, and the controller drops an answer of another run.
World-delta stream: strictly ordered, sequence-numbered, carrying chunk state and per-block deltas. Supports Kafka-style "resume from last N" on reconnect. Every resident chunk is sent again only if a node has fallen far behind. An assignment names the sequence it stands at, so a node checks even the first frame after it. A node that cannot apply a world frame drops all world state and reconnects reporting nothing held, so its area is sent again; there is no NACK. A world frame whose encode fails is encoded again under the same sequence.
Pathfinding-request stream: at-least-once, idempotent. A request still unanswered a tick after its node should have served it (counting the requests the node holds ahead of it when it leaves) is resent under the same id, at most twice. A request whose mob no longer wants it is canceled, best effort: the node drops it if it has not started it, along with any later copy, and the controller still counts it against the node until its answer is due. Last-write-wins if two responses land in the same tick, otherwise first response wins. A node never waits for world state: it answers against what it holds and reports the sequence it used, and an answer counts only if its node held the chunk the search starts in by that sequence. A node keeps an answer or a cancel for 1 s, twice the 10 ticks after which the controller gives up, and drops unserved a request that waited longer than 1 s.
Requests are rejected pre-send (not on response) if a node's queue depth implies completion more than 10 ticks after the current world state.

SCALING AND FAILOVER
Region ownership is controller-authoritative with no external coordination. Regions are cells of a fixed 256-block lattice, one centered on the origin; a static fleet (the configured `nodes`) holds the cells in spiral order out from it, one each. Region ids are never reused within a controller run, a region's sequence stream is monotonic across owners, and the run id is exchanged on connect, so a reconnecting node is placed by what it reports holding. Adding a node splits an existing node's region. Node death triggers reassignment of its region to another node via a fresh snapshot from the server. During handoff, mobs in the affected region are treated as dropped by the main server until reassignment completes.
Hot nodes (many mobs): since node workload is read-only, replicate the hot node and split load if fleet capacity allows; if fleet is maxed out, shed load per the SLO policy.
Liveness detection via phi accrual failure detector. Nodes push an unsolicited heartbeat carrying their queue depth on their own timer; the detector reads the intervals between arrivals against the controller's clock, so nothing is solicited and the two clocks are never compared.
On node failure: mobs with a path computed within the last 10 ticks continue on that path. Mobs without a recent path get a cheap heuristic path computed on the main server. A small compute budget (<= 1000 microseconds/tick) is reserved on the main thread to run full A* for a limited number of mobs, round-robin, prioritizing those nearest to a player, until the node recovers. Those mobs are served by passing the interception through to vanilla. The cheap path is vanilla's search on a sixteenth of its node budget, and mobs wait for full A* in the order they asked, each 16 blocks from the nearest player counting as one tick later.

SLO
p99 latency < 3 ticks. Framed as latency, but the real target is throughput under a latency budget. When a saturated fleet can't meet the SLO, drop mobs that are furthest from any player or not actively hunting.

TESTING
Fuzz testing compares Maestro vs vanilla Minecraft pathfinding by malus-weighted A* path cost across randomly generated regions. Test worlds are superflat with mild hills and obstacles but no overhangs or caves, so world state is a single vertical band per column. Some margin of error allowed since vanilla pathfinding isn't always optimal; this testing is for statistics/observability, not strict correctness.
Vanilla parity fixtures (`fixtures/parity`, regenerated by `make capture`) record real vanilla searches on seeded terrain through the `/maestro capture <seed> <cases>` command, which only a dev server has (it lives in a separate dev mod, not the released jar). Block changes between searches are recorded as delta frames. A case is exact when the node's stand-in for the mob's position (the bottom centre of the start node) gave the search the same inputs, and every collision and floor query vanilla made got the same answer from the node's cell model; the node must reproduce every exact case, and the rest are measured only. These are also the wire fixtures shared by the Java and C++ tests.
Deterministic simulation testing (DST) is the primary correctness mechanism for the Java controller's distributed logic: stream sequencing, resume-from-N, resharding, phi accrual, node loss and handoff, at-least-once duplicate delivery, last-write-wins, and queue-depth rejection. Scope is the controller only. Minecraft is an input source, not a participant: the simulation consumes tick boundaries, block changes, and mob requests through the world boundary interface, fed by a trace instead of by mixins. Compute nodes are modeled, not run; the real C++ node is covered by unit tests plus wire-level fixtures shared with the Java side, and the model and the node both replay the conformance scripts in `fixtures/conformance` (written by `make conformance`), so the model cannot drift from the node. The model serves requests on workers with a seeded cost per request, and the controller assumes a capacity drawn apart from the true one. Runs use spec-size regions (256 blocks) cut from the production lattice, with chunks loaded around spawn and players as on a server, and some regions replicated. Simulated time is tick-driven with a deterministic intra-tick event queue. The controller runs on the server thread, so the network and finished offload work reach it only at two hand-overs per tick, when the tick starts and when its work ends; the simulator models this, and draws how much of each tick the server works. Runs are seeded and any failure replays from its seed. The simulator controls message delivery order, latency, drops, duplicates, node death and pauses, controller restarts, and server ticks that run long or stall. Every setting a run has (region geometry, world floor/height/relief, fleet size and per-node capacity, mob and player counts, mob profiles, event rates, latency range, run length, and the fault plan) is drawn from the seed, so a sweep covers settings and not only event orderings. The seed sweeps are tagged `fuzz` and run as their own Gradle task and CI job (`make fuzz SEED=n RUNS=n`), separate from the unit suite (`make test`). Invariants asserted: per-region sequence monotonicity with no gaps, across resnapshots too (a fresh assignment never starts behind a frame already sent to a holder of the region), state after failover equal to a fresh full recomputation, at the end of a run and at seeded checkpoints during it, every live node caught up once faults end, every request answered or explicitly dropped exactly once, no answer searched over air accepted, duplicate delivery idempotent, a node that cannot answer (paused, partitioned, or losing its datagrams) sent no new requests once enough went unanswered to show it, past one probe per backoff, and p99 within the tick budget whenever the load fits the fleet's capacity and the server keeps up with its ticks, judged from the offered load and the fleet, not from what the controller did, with no node taken out of service in a run whose load fits, even one whose server stalls or falls behind. A request that should have been served (its start chunk long loaded in a region) and was dropped for want of a node counts as late, as does one lost with its node.
An end-to-end test (`make test-e2e`) runs the released mod against a real node on loopback, in shadow mode, where the node's answers must match vanilla's, with its answers moving the mobs, and through a node pause and a node crash and restart, where the failover must serve the mobs and the node must come back into service. Mod tests that need the mixins applied run under Fabric's JUnit loader (`mixinTest`), apart from the plain unit tests, since the loader refuses to read block tags no server bound.
Live trials run on single-AZ AWS compute nodes. ChaosMonkey and tc used to test failover under network/node faults. A reproducible load generator is needed for live experiments.

OBSERVABILITY
OpenTelemetry used throughout. Trace ids derive from the run and request ids, so the wire carries none and a DST seed names its traces. Metrics/traces needed: end-to-end request tracing, per-node consumer lag (Kafka-style), RED metrics per-request, USE metrics per-server, distribution of ticks-late per pathfind response (for SLO visualization), node topology visualization (resharding events, phi values over time), and per-node work queue depth.
