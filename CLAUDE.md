MAESTRO

PROJECT OVERVIEW

Server-side Minecraft 26.1 mod, pinned permanently (no version updates). Offloads in-game A* pathfinding computation from the Java server to horizontally scalable C++20 compute nodes, allowing mob counts beyond vanilla limits. Purpose is educational: an experiment in latency-sensitive, high-availability distributed systems, not a polished gameplay mod.

COMPONENTS
Java server mod: authoritative world state, mob/tick logic, node orchestration, failover. Pathfinding is intercepted at `PathFinder.findPath` for single-target searches whose path finder and evaluator are exactly `PathFinder` and `WalkNodeEvaluator`; subclasses (the Warden's path finder, the Creaking's evaluator) and everything else stay vanilla. So does a search in which two nodes could share vanilla's lossy node hash (`Node.createHash`), which the node's exact node table cannot reproduce. The start node and the profile are resolved on the server between the evaluator's `prepare` and `done`, since `onPathfindingStart` may change malus (the Sniffer's). A call issues a request and returns the mob's latest fresh result, or null.
C++20 compute nodes: run A* pathfinding on world data sent by the server. The search sits behind one interface, chosen once at startup and reported on connect.
Wire protocol: Flatbuffers. Blocks sent as Minecraft PathType enum ordinals, not raw block types (the PathType enum is mirrored in the schema so the ordinal contract is explicit). Cells carry the per-block PathType (getPathTypeFromState, a pure function of one block state) and the block's collision height in sixteenths; neighbor-dependent and mob-dependent types are resolved on the node at query time, which keeps the delta contract at exactly one cell per block change. Chunk state is column run-length encoded, so its size tracks terrain complexity rather than world height. Mob metadata sent as low-cardinality IDs plus relative start/target positions and the per-call search inputs: reach range, the path length and visit bounds, and the mob's max fall distance (getMaxFallDistance reads its target and health, so it varies per call). The WalkNodeEvaluator inputs (footprint, per-PathType malus, and door/step/float/fence capabilities) are live per-instance state, not per-type: goals and mob code change malus and door abilities at runtime, and footprint varies with age, so a profile is interned by content and named per request. The first request naming a profile a node does not hold registers it and is given up, which normally keeps the profile a tick ahead of any request that needs it; a request that still overtakes it (a TCP retransmit can hold the control channel back) is answered `UnknownProfile` and dropped. Buffers reused, serialization done off main thread to avoid GC/lag.

COMPUTATION SEMANTICS
Best effort and eventually consistent. The node rebuilds getPathTypeStatic from the per-block types it holds: the OPEN-over-solid promotion that reads the cell below, then checkNeighbourBlocks. That scan must match vanilla exactly, including its dx/dy/dz iteration order over -1..1 skipping the center column, and its return on first hazard found, which is what decides cells bordering more than one hazard. Only A* is offloaded; other mob movement types (e.g. random walk) stay local. Scoped to land mobs only: the offload reproduces Minecraft's ground pathfinding (WalkNodeEvaluator); swimming, flying and amphibious evaluators stay local. Wall climbing is navigation behaviour rather than an evaluator, so a climbing mob's search is offloaded and its climbing stays on the server. Overworld only, no other dimensions (disabled by the mod). The wire carries each block's collision height, rounded up to a sixteenth, but not its shape, so `getFloorLevel` is exact to that sixteenth (only rare shapes such as the lily pad at 1.5/16 move) and `hasCollisions` treats every cell as a full-width box of that height, read without the mob, so blocks whose collision depends on the entity (powder snow, scaffolding) can differ. These approximations are intentional, as is ignoring the world border, which vanilla's collision checks include. Vanilla's search sees no entity collisions (its `PathNavigationRegion` holds none), so the node matches it there. Cells carry no fluid, so "in water" means a cell typed WATER. The node never receives the mob's position: the two evaluator branches that read it (the collision sweep off a fence or closed door, and the rail check) use the start node instead. Otherwise the search is a decision-for-decision port of PathFinder and WalkNodeEvaluator, float rounding and tie-breaking included.

NODE MODES
Stateful (default): nodes hold delta-synced world shards, sent a chunk at a time. A node holds its whole area as air until a chunk arrives, which is what vanilla reads for a chunk the server is not holding, so a region serves requests without waiting to be complete and a chunk leaving costs one frame rather than a resend of the region. World divided into square, full-height regions with a halo buffer around each, so mobs near a boundary are shared with neighboring nodes. Columns are carried at full height with no vertical trimming: run-length encoding already makes height nearly free. The halo is one pathfinding horizon wide (~64 blocks) and its cost grows as ((R + 2H) / R)^2, so region size is at least 4x the horizon (~256 blocks). A node reads past its area as air, so a request is sent only if every block its search reads lies in the area: `ceil(maxPathLength) + floor(width + 1) + 1` blocks around its start horizontally; otherwise it stays on the server. A node holds its area as immutable versions: a delta publishes a new version sharing untouched columns, and a search pins one version throughout. Two sub-modes, both to be benchmarked: batch (all mob requests within a tick sent together, +/- jitter) and stream (requests sent immediately).
Stateless: nodes receive a full snapshot per request, trimmed to pathfinding-relevant surface blocks only (not the entire world). Distributed across nodes via power-of-2-choices. Sharding/halo concepts don't apply in this mode. Bandwidth inefficiency is intentional, for comparison purposes; no RLE or similar compression, to keep complexity down.

DATA STREAMS
Two separate streams: world changes and mob pathfinding requests. World and control streams are TCP; the request stream is UDP, one frame per datagram.
World-delta stream: strictly ordered, sequence-numbered, carrying chunk state and per-block deltas. Supports Kafka-style "resume from last N" on reconnect. Every resident chunk is sent again only if a node has fallen far behind. A node that cannot apply a world frame drops all world state and reconnects reporting nothing held, so its area is sent again; there is no NACK. A world frame whose encode fails is encoded again under the same sequence.
Pathfinding-request stream: at-least-once, idempotent. A request still unanswered a tick after it leaves is resent under the same id, at most twice. Last-write-wins if two responses land in the same tick, otherwise first response wins. A node never waits for world state: it answers against what it holds and reports the sequence it used.
Requests are rejected pre-send (not on response) if a node's queue depth implies completion more than 10 ticks after the current world state.

SCALING AND FAILOVER
Region ownership is controller-authoritative with no external coordination. Region ids are never reused within a controller run, a region's sequence stream is monotonic across owners, and the run id is exchanged on connect, so a reconnecting node is placed by what it reports holding. Adding a node splits an existing node's region. Node death triggers reassignment of its region to another node via a fresh snapshot from the server. During handoff, mobs in the affected region are treated as dropped by the main server until reassignment completes.
Hot nodes (many mobs): since node workload is read-only, replicate the hot node and split load if fleet capacity allows; if fleet is maxed out, shed load per the SLO policy.
Liveness detection via phi accrual failure detector. Nodes push an unsolicited heartbeat carrying their queue depth on their own timer; the detector reads the intervals between arrivals against the controller's clock, so nothing is solicited and the two clocks are never compared.
On node failure: mobs with a path computed within the last 10 ticks continue on that path. Mobs without a recent path get a cheap heuristic path computed on the main server. A small compute budget (<= 1000 microseconds/tick) is reserved on the main thread to run full A* for a limited number of mobs, round-robin, prioritizing those nearest to a player, until the node recovers. Those mobs are served by passing the interception through to vanilla.

SLO
p99 latency < 3 ticks. Framed as latency, but the real target is throughput under a latency budget. When a saturated fleet can't meet the SLO, drop mobs that are furthest from any player or not actively hunting.

TESTING
Fuzz testing compares Maestro vs vanilla Minecraft pathfinding by malus-weighted A* path cost across randomly generated regions. Test worlds are superflat with mild hills and obstacles but no overhangs or caves, so world state is a single vertical band per column. Some margin of error allowed since vanilla pathfinding isn't always optimal; this testing is for statistics/observability, not strict correctness.
Vanilla parity fixtures (`fixtures/parity`, regenerated by `make capture`) record real vanilla searches on seeded terrain through the `/maestro capture <seed> <cases>` command, which only a dev server has (it lives in a separate dev mod, not the released jar). Block changes between searches are recorded as delta frames. A case is exact when the node's stand-in for the mob's position (the bottom centre of the start node) gave the search the same inputs, and every collision and floor query vanilla made got the same answer from the node's cell model; the node must reproduce every exact case, and the rest are measured only. These are also the wire fixtures shared by the Java and C++ tests.
Deterministic simulation testing (DST) is the primary correctness mechanism for the Java controller's distributed logic: stream sequencing, resume-from-N, resharding, phi accrual, node loss and handoff, at-least-once duplicate delivery, last-write-wins, and queue-depth rejection. Scope is the controller only. Minecraft is an input source, not a participant: the simulation consumes tick boundaries, block changes, and mob requests through the world boundary interface, fed by a trace instead of by mixins. Compute nodes are modeled, not run; the real C++ node is covered by unit tests plus wire-level fixtures shared with the Java side. Simulated time is tick-driven with a deterministic intra-tick event queue. Runs are seeded and any failure replays from its seed. The simulator controls message delivery order, latency, drops, duplicates, and node death. Every setting a run has (region geometry, world floor/height/relief, fleet size and per-node capacity, mob and player counts, mob profiles, event rates, latency range, run length, and the fault plan) is drawn from the seed, so a sweep covers settings and not only event orderings. The seed sweeps are tagged `fuzz` and run as their own Gradle task and CI job (`make fuzz SEED=n RUNS=n`), separate from the unit suite (`make test`). Invariants asserted: per-region sequence monotonicity with no gaps, across resnapshots too, state after failover equal to a fresh full recomputation, every live node caught up once faults end, every request answered or explicitly dropped exactly once, duplicate delivery idempotent, and p99 within the tick budget whenever the load fits the fleet's capacity.
Live trials run on single-AZ AWS compute nodes. ChaosMonkey and tc used to test failover under network/node faults. A reproducible load generator is needed for live experiments.

OBSERVABILITY
OpenTelemetry used throughout. Trace ids derive from the run and request ids, so the wire carries none and a DST seed names its traces. Metrics/traces needed: end-to-end request tracing, per-node consumer lag (Kafka-style), RED metrics per-request, USE metrics per-server, distribution of ticks-late per pathfind response (for SLO visualization), node topology visualization (resharding events, phi values over time), and per-node work queue depth.
